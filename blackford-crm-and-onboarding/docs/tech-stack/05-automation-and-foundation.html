The 17 automations; Modules B, F, G

Automation engine

No users · runs in the background on Cloud Run

Built with

RuntimeNode.js and TypeScript on an always-on Cloud Run service
JobsGraphile Worker, with jobs and schedules stored in PostgreSQL
Email and textAmazon SES and AWS End User Messaging
TemplatesLiquidJS merge fields in English and Spanish
PDFsPuppeteer for forms and confirmations; pdf-lib to fill carrier forms
Carrier filesCSV, OpenPGP encryption where required, SFTP from a fixed IP address
Release 2Ideon or Noyo connections; ACA forms through the filing vendor

What it handles

  • Invites and reminders at 7, 3 and 1 days, within quiet hours
  • Channel fallback, escalations and follow-up tasks
  • Nightly checks: missing data, dependents turning 26, clients turning 65
  • Life-event windows and the 120-day renewal start
  • Carrier change files, approval queue, delivery and follow-up
  • A nightly check that the audit log is intact

Safeguards

  • A job is saved only when its data change is saved
  • Jobs carry record IDs, never health details
  • Every run is logged; any automation can be paused per group

infra/terraform

Data and infrastructure

Shared by every platform · Google Cloud, under the BAA

Built with

DatabasePostgreSQL on Cloud SQL: private network only, customer-managed encryption keys, point-in-time recovery
Data accessDrizzle ORM behind one core layer; row-level security on every client table
Audit logAppend-only and hash-chained, so any edit is detectable
Sensitive fieldsSocial Security numbers encrypted again with Cloud KMS and matched by keyed hash
FilesCloud Storage buckets with public access blocked
EdgeLoad balancer, managed certificates, Cloud Armor firewall and rate limits
OperationsCloud Logging and Monitoring, Terraform, GitHub Actions with keyless deploys

What it provides

  • One data model for every module and release
  • Separate dev, staging and production environments
  • Backups, with restores tested on staging
  • Alerts when a job, the load balancer or the audit chain fails

Safeguards

  • Without a signed-in user's context, the database returns nothing
  • Logs and alerts never contain client data
  • Only production ever holds real client data
