Outside services and their agreements

At launch, client data reaches two outside clouds, Google Cloud and AWS, both under a BAA. Carriers receive approved files, and with signing built in, nothing else sees client data.

Service Provider Agreement Client data it receives When
Cloud hosting Google Cloud: Cloud Run, Cloud SQL, Identity Platform, Cloud Storage, Cloud KMS Google Cloud BAA All platform data, encrypted at rest and in transit MVP
Email and text AWS: SES for email, End User Messaging for SMS AWS BAA, accepted online in AWS Artifact Names, contact details and secure links; no health details in texts MVP
E-signature Built into the platform (recommended), or an e-signature vendor None if built in; a vendor needs its own BAA None if built in MVP · Decide by Dec 11
Insurance carriers Each carrier, by CSV file over SFTP, PGP-encrypted where required Each carrier's file and delivery terms Enrollment data in the carrier's own template MVP
Carrier APIs Ideon or Noyo Contract and BAA with Blackford and Hyacinth Enrollment data for connected carriers Release 2
ACA filing ACA filing vendor, to be selected BAA or data agreement 1094 and 1095 form data, including SSNs Release 2
TPAs Each self-funded group's third-party administrator Data agreement per TPA Billing, claims and fee reports, imported Release 3
Security testing Outside penetration testing firm, booked by Jan 15, 2027 NDA and test plan None: tests run on staging with test data Each release
Code and deploys GitHub: repository, reviews, CI/CD Standard terms None: client data is never allowed in the repository Throughout
Why AWS for messages. Twilio also works for texts, but it signs a BAA only on its Security or Enterprise Edition, bought through its sales team. The AWS BAA is accepted online, which keeps the texting registration on schedule.
